# Тест-кейси для Intelligent Currency Tracker

## Тест План

### Мета тестування
Забезпечити якість та надійність додатку Intelligent Currency Tracker шляхом систематичного тестування всіх критичних компонентів системи.

### Область тестування
- Репозиторії даних (RateRepository, CurrencyRepository)
- Бізнес-логіка сервісів (RateService, PostService, ReportService)
- API-контролери (RatesController, PostsController)
- Інтеграція з зовнішніми системами (Kafka, MinIO, NBU API)
- Користувацький інтерфейс (UI компоненти Blazor)

### Типи тестування
- **Модульне тестування:** Перевірка окремих компонентів у ізоляції
- **Інтеграційне тестування:** Перевірка взаємодії між компонентами
- **Функціональне тестування:** Перевірка бізнес-вимог
- **Тестування продуктивності:** Перевірка швидкодії та масштабованості
- **Тестування безпеки:** Перевірка авторизації та захисту даних

### Ресурси
- **Тестувальник:** Автоматизовані тести
- **Інструменти:** xUnit, Moq, FluentAssertions, EntityFrameworkCore.InMemory
- **Середовище:** Локальна розробка, CI/CD pipeline

### Графік
- Модульні тести: Під час розробки кожного компонента
- Інтеграційні тести: Після завершення спринту
- Регресійне тестування: Перед кожним релізом

### Приклад звіту про дефект

**ID:** BUG-001  
**Серйозність:** Висока  
**Статус:** Виправлено  

**Опис:** RateRepository.GetLastByCurrencyIdAsync викидає NullReferenceException замість EntityNotFoundException при відсутності курсів

1. Викликати GetLastByCurrencyIdAsync з валідним currencyId
2. Переконатися, що в базі даних немає курсів для цієї валюти

**Очікувана поведінка:** Має викинутися EntityNotFoundException<Rate>  
**Фактична поведінка:** Викидається NullReferenceException  

**Виправлення:** Додано перевірку на порожній результат перед доступом до властивостей

## Набір тестів 1: Тести RateRepository

### Тест-кейс 1.1: GetLastByCurrencyIdAsync - Успішний сценарій

**Тестовий метод:** `GetLastByCurrencyIdAsync_ShouldReturnLatestRate_WhenRatesExist`

**Опис:** Перевірити, що репозиторій правильно отримує найновіший курс для заданої валюти, коли існує декілька курсів.

**Тип тесту:** Модульний тест (Інтеграція з базою даних у пам'яті)

**Передумови:**
- База даних у пам'яті ініціалізована
- Тестова валюта (USD, R030=840) існує в базі даних
- Для валюти існують два курси:
  - Старіший курс: Value = 27.5, Date = 2 дні тому
  - Новіший курс: Value = 28.0, Date = 1 день тому

**Кроки тестування:**
1. Arrange: Створити тестову валюту та додати до бази даних
2. Arrange: Створити два записи курсів з різними датами
3. Arrange: Зберегти курси в базу даних у пам'яті
4. Act: Викликати `GetLastByCurrencyIdAsync(currencyId)`
5. Assert: Перевірити, що повернутий курс відповідає найновішому курсу

**Очікуваний результат:**
- Метод повертає об'єкт Rate з найновішою датою
- Rate.Id відповідає ID найновішого курсу
- Rate.Value дорівнює 28.0
- Rate.Date знаходиться в межах 1 секунди від дати найновішого курсу

**Фактичний результат:** ПРОЙДЕНО
- Репозиторій правильно повернув найновіший курс
- Усі перевірки пройдені успішно
- Час виконання: ~10мс

### Тест-кейс 1.3: GetRangeAsync - Тест пагінації

**Тестовий метод:** `GetRangeAsync_ShouldReturnRatesInDateRange_WithPagination`

**Опис:** Перевірити, що репозиторій правильно повертає курси у діапазоні дат з належною підтримкою пагінації.

**Тип тесту:** Модульний тест (Логіка пагінації)

**Передумови:**
- База даних у пам'яті ініціалізована
- Тестова валюта існує
- Існує 15 записів курсів протягом 15 днів (день -10 до дня -1)
- Кожен курс збільшується на 0.1 (27.0, 27.1, 27.2, ... 27.4, ...)

**Кроки тестування:**
1. Arrange: Створити 15 послідовних записів курсів
2. Arrange: Зберегти всі курси в базу даних
3. Act: Викликати `GetRangeAsync(startDate, endDate, page=1, pageSize=5)`
4. Assert: Перевірити, що повернуто лише 5 курсів (перша сторінка)
5. Assert: Перевірити, що повернуті курси в правильному порядку
6. Assert: Перевірити, що значення першого курсу 27.0, а останнього 27.4

**Очікуваний результат:**
- Повернуто рівно 5 курсів (розмір сторінки)
- Курси впорядковані за датою за зростанням
- Перший курс має Value = 27.0
- Останній курс має Value = 27.4
- Пагінація правильно пропускає 0 записів для сторінки 1

**Фактичний результат:** ПРОЙДЕНО
- Репозиторій повернув рівно 5 курсів
- Курси були правильно впорядковані
- Значення відповідали очікуваному зрізу пагінації
- Час виконання: ~492мс

## Набір тестів 2: Тести RateService

### Тест-кейс 2.1: GetAllCurrenciesAsync - Успішний сценарій

**Тестовий метод:** `GetAllCurrenciesAsync_ShouldReturnCurrencies_WhenCurrenciesExist`

**Опис:** Перевірити, що сервіс правильно отримує всі валюти та мапить їх у DTO, коли валюти існують у системі.

**Тип тесту:** Модульний тест (з мокуванням)

**Передумови:**
- Мок-репозиторії налаштовані
- Тестові дані включають дві валюти:
  - USD (R030=840, Code="USD", Name="US Dollar")
  - EUR (R030=978, Code="EUR", Name="Euro")

**Кроки тестування:**
1. Arrange: Налаштувати мок репозиторію валют для повернення 2 тестових валют
2. Arrange: Налаштувати мок маппера для конвертації сутностей Currency у DTO
3. Act: Викликати `GetAllCurrenciesAsync()`
4. Assert: Перевірити, що результат не null і Success = true
5. Assert: Перевірити, що тип результату GetAllCurrenciesResult
6. Assert: Перевірити, що колекція Currencies містить 2 елементи
7. Assert: Перевірити, що присутні обидва коди USD та EUR
8. Assert: Перевірити, що репозиторій викликано рівно один раз

**Очікуваний результат:**
- Повертає BaseResult з Success = true
- Результат типу GetAllCurrenciesResult
- Колекція Currencies містить 2 DTO
- DTO містять коди валют "USD" та "EUR"
- CurrencyRepository.GetAllAsync() викликано рівно один раз
- Mapper.Map<CurrencyDto>() викликано для кожної валюти

**Фактичний результат:** ПРОЙДЕНО
- Сервіс повернув успішний результат
- Усі валюти були правильно змапені
- Верифікація мока підтвердила правильні виклики методів
- Час виконання: ~25мс

### Тест-кейс 2.3: GetDetailsAsync - Сценарій відсутності курсів

**Тестовий метод:** `GetDetailsAsync_ShouldReturnFailure_WhenNoRatesFound`

**Опис:** Перевірити, що сервіс повертає результат з помилкою, коли не існує курсів для вказаної валюти та діапазону дат.

**Тип тесту:** Модульний тест (Випадок невдачі з мокуванням)

**Передумови:**
- Мок-репозиторії налаштовані
- Тестова валюта існує (USD)
- Діапазон дат: 30 днів тому до сьогодні
- Курсів не існує у вказаному діапазоні дат

**Кроки тестування:**
1. Arrange: Створити тестову валюту (USD)
2. Arrange: Налаштувати мок репозиторію валют для повернення валюти
3. Arrange: Налаштувати мок репозиторію курсів для повернення порожнього списку
4. Act: Викликати `GetDetailsAsync("USD", startDate, endDate)`
5. Assert: Перевірити, що результат не null
6. Assert: Перевірити, що Success = false
7. Assert: Перевірити, що Errors містить конкретне повідомлення
8. Assert: Перевірити, що обидва репозиторії викликані один раз

**Очікуваний результат:**
- Повертає BaseResult з Success = false
- Масив Errors містить: "No rates found for the specified currency and date range."
- CurrencyRepository.GetByCodeAsync("USD") викликано один раз
- RateRepository.GetRangeAsync() викликано один раз з правильними параметрами
- Виняток не викидається (коректна обробка помилки)

**Фактичний результат:** ПРОЙДЕНО
- Сервіс повернув результат з помилкою як очікувалось
- Повідомлення про помилку було правильно включено
